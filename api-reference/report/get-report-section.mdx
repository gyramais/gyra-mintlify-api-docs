### Quando usar

Use esta rota quando você tem o ID do relatório e quer um bloco específico (score, processos, balanço) sem carregar o relatório inteiro. O `sectionType` é a chave estável da seção: não muda entre ambientes nem entre relatórios.

### Autenticação

Bearer JWT no header `Authorization`. Um relatório de outra organização responde `404`.

### Parâmetros

| Nome | Local | Tipo | Obrigatório | Descrição |
|---|---|---|---|---|
| `id` | `path` | `string` | sim | ID do relatório. |
| `sectionType` | `path` | `string` | sim | Tipo da seção, em maiúsculas. Lista abaixo. |

### Tipos de seção

Quais seções existem num relatório depende do [tipo de relatório](/docs/tipos-relatorios), do documento (CPF ou CNPJ) e das fontes da política. A coluna **Parecer IA** marca as seções que recebem [Parecer GYRA+ IA](/concepts/pareceres-gyra-ia) quando o parecer está habilitado no relatório.

**Análise e risco**

| `sectionType` | Seção | Parecer IA |
|---|---|---|
| `SUMMARY` | Resumo, indicadores consolidados de risco | não |
| `BASIC_INFORMATION` | Informações básicas, dados cadastrais e QSA | sim |
| `LOCATION` | Localização e fachada do endereço | sim |
| `RELATIONS` | Vínculos societários e grupo econômico | sim |
| `SCORE` | Score de bureau | sim |
| `POSITIVE_REGISTRY` | Cadastro Positivo | sim |
| `PROCESSES` | Processos judiciais | sim |
| `JUDGMENTS` | Ações judiciais | sim |
| `CERTIFICATES` | Certidões | sim |
| `LICENSES_AUTHORIZATIONS` | Licenças e autorizações | sim |
| `PEP` | Pessoa politicamente exposta | sim |
| `SANCTIONS` | Sanções e listas restritivas | sim |
| `MEDIA_EXPOSURE` | Exposição em mídia e reputação | sim |
| `CRIMINAL_RECORD` | Antecedentes criminais e mandados de prisão (CPF) | sim |
| `SOCIAL_ASSISTANCE_PROGRAMS` | Programas sociais e benefícios (CPF) | sim |
| `SECTOR` | Panorama setorial e macroeconômico | sim |

**Restritivos e endividamento**

| `sectionType` | Seção | Parecer IA |
|---|---|---|
| `SCR` | SCR, categorias e modalidades | sim |
| `SCR_SUMMARY` | Resumo SCR, endividamento consolidado | sim |
| `SCR_INDICATORS` | Indicadores do SCR | não |
| `PEFIN` | Pefin | sim |
| `REFIN` | Refin | sim |
| `PROTESTS` | Protestos em cartório | sim |
| `BAD_CHECK` | Cheques sem fundo | sim |
| `PAST_DUE_DEBT` | Dívidas vencidas | sim |
| `PAYMENT_INTELLIGENCE` | Inteligência de Pagamentos | não |

**Análise financeira** (CNPJ, depois que o balanço entra no relatório)

| `sectionType` | Seção | Parecer IA |
|---|---|---|
| `BALANCE_SHEET` | Balanço patrimonial | não |
| `DRE` | Demonstração do resultado do exercício | não |
| `FINANCIAL_INDICATORS` | Indicadores financeiros calculados | não |
| `FINANCIAL_INSIGHTS` | Resumo executivo da análise financeira | não |
| `FINANCIAL_RECOMMENDATIONS` | Recomendações da análise financeira | não |
| `BALANCE_SHEET_CHART` | Séries do balanço para gráficos | não |
| `COST_PROFIT_FORECAST` | Projeção de custo e resultado | não |
| `DETAILED_COSTS` | Custos detalhados | não |
| `SUPPLIERS_CLIENTS` | Fornecedores e clientes | não |

<Note>
  A leitura de IA do balanço não é um Parecer IA de seção: ela sai junto com a própria análise financeira, na seção `FINANCIAL_INSIGHTS`. As seções financeiras passam a existir quando a GYRA+ encontra as demonstrações ou quando você as envia em [Enviar Balanço e DRE](/api-reference/report/post-report-financial-tab).
</Note>

**Complementares e resultado da política**

| `sectionType` | Seção | Parecer IA |
|---|---|---|
| `CATEGORIES` | Categorias de atividade | não |
| `HISTORY` | Histórico cadastral | não |
| `DOMAINS` | Domínios de internet associados | não |
| `BUREAU_INQUIRY` | Consultas ao bureau | não |
| `CREDIT_POLICY` | Resultado da avaliação da política de crédito | não |
| `PRICING` | Limite, taxa e prazo calculados pela política | não |
| `INPUT_DATA` | Dados de entrada da proposta | não |

<Warning>
  Um `sectionType` válido que não existe naquele relatório responde `404` com `"Seção não encontrada"`, não vazio. Um valor que não é tipo de seção responde `404` com `"Tipo de seção não encontrado"`. Para saber quais seções o relatório tem, leia `sections[]` em [`GET /v2/report/{id}`](/api-reference/report-v2/get-v2report).
</Warning>

<RequestExample>

```bash cURL
curl --request GET 'https://gyra-core.gyramais.com.br/report/6612a7f3a19b467000000000/section/PROTESTS' \
  --header 'Authorization: Bearer SEU_TOKEN'
```

```javascript JavaScript
const resposta = await fetch(
  "https://gyra-core.gyramais.com.br/report/6612a7f3a19b467000000000/section/PROTESTS",
  { headers: { Authorization: `Bearer ${token}` } },
);
const secao = await resposta.json();
```

```python Python
import requests

resposta = requests.get(
    "https://gyra-core.gyramais.com.br/report/6612a7f3a19b467000000000/section/PROTESTS",
    headers={"Authorization": f"Bearer {token}"},
)
secao = resposta.json()
```

</RequestExample>

### Erros

| Código | Mensagem | Causa |
|---|---|---|
| `404` | `"Relatório não encontrado"` | ID inexistente ou de outra organização. |
| `404` | `"Tipo de seção não encontrado"` | `sectionType` fora da lista acima. |
| `404` | `"Seção não encontrada"` | O relatório não tem essa seção. |
