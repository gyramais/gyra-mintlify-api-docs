<Info>
  **Resumo:** os dois recursos seguem a mesma política da régua: **salvar publica uma versão nova** e a anterior nunca é reescrita. O endereço estável é o `slug` (modelo de coleta) ou a `key` (modelo de termo).
</Info>

## Modelos de coleta

Prefixo `/v1/collection-templates`.

| Método | Caminho | O que faz |
| --- | --- | --- |
| `POST` | `/collection-templates` | Cria um modelo |
| `GET` | `/collection-templates` | Lista os modelos vigentes com métricas de uso |
| `GET` | `/collection-templates/{id}` | Consulta um modelo |
| `PUT` | `/collection-templates/{id}` | Publica uma versão nova |
| `POST` | `/collection-templates/{id}/duplicate` | Duplica numa cópia editável |
| `DELETE` | `/collection-templates/{id}` | Remove (soft delete) |

### Corpo

```json
{
  "name": "Onboarding PJ",
  "slug": "onboarding-pj",
  "description": "Documentos mínimos para abrir limite de PJ.",
  "dueInDays": 10,
  "reminders": [2, 5, 8],
  "channel": "BOTH",
  "responseMode": "REVIEW",
  "behavior": {
    "acceptPartial": false,
    "requestResendOnReject": true,
    "notifyOnComplete": true,
    "skipItemsAlreadyOnFile": true,
    "blockSignatureUntilDependenciesMet": true,
    "requireCoSignerContacts": false
  },
  "items": [
    {
      "key": "constitutivo",
      "kind": "DOCUMENT",
      "requirement": "CONSTITUTIVO_VIGENTE",
      "label": "Documento constitutivo vigente",
      "required": true,
      "rules": { "maxAgeDays": 365, "allowMultipleFiles": true, "maxFiles": 5 }
    },
    {
      "key": "identidade-socios",
      "kind": "DOCUMENT",
      "documentType": "DOC_IDENTIDADE",
      "label": "Documento de identidade",
      "required": true,

    },
    {
      "key": "dados-da-empresa",
      "kind": "FORM",
```

### Campos do modelo

| Campo | Obrigatório | Nota |
| --- | --- | --- |
| `name` | sim | |
| `slug` | não | Derivado do nome quando ausente. **É o endereço estável** usado ao criar solicitação |
| `description` | não | |
| `items[]` | sim | Ao menos um |
| `dueInDays` | não | 1 a 365; padrão 7 |
| `reminders[]` | não | Dias após o envio; padrão `[2, 5]` |
| `channel` | não | `EMAIL`, `WHATSAPP`, `BOTH`, `NONE` |
| `responseMode` | não | `AUTOMATIC` ou `REVIEW` |
| `behavior` | não | Ver a tabela em [Solicitações de coleta](/kyc/solicitacoes#comportamento-do-modelo) |

### Campos do item

| Campo | Nota |
| --- | --- |
| `key` | kebab-case; derivado do rótulo quando ausente. Estável entre versões |
| `kind` | `DOCUMENT`, `FORM`, `CONSENT`, `SIGNATURE`, `IDENTITY`, `CUSTOM` |
| `documentType` | Obrigatório em `DOCUMENT`, **a não ser que** o item declare `requirement` |
| `requirement` | `CONSTITUTIVO_VIGENTE` ou `REPRESENTACAO_VIGENTE`. Alternativa a `documentType`, nunca companhia |
| `label` | Em português; é o que o destinatário lê |
| `instructions` | Instrução opcional |
| `required` | |
| `perPerson` | Um item por destinatário pessoa física |
| `consentType` | Obrigatório em `CONSENT`. Hoje: `SCR` |
| `consentTemplateId` | Termo escolhido pelo id |
| `formSpec` | Obrigatório em `FORM`. Ver [Formulários](/kyc/formularios) |
| `signatureMode` | `INDIVIDUAL` (padrão) ou `JOINT` |
| `signaturePackage` | `SIGNATURE` (padrão) ou `SIGNATURE_AND_IDENTITY` |
| `allowSignatoryInvite` | Uma parte pode incluir outra pela página do destinatário |
| `maxSignatories` | Padrão 10, limite absoluto 50 |
| `rules` | Regras da coleta. Ver a tabela em [Solicitações de coleta](/kyc/solicitacoes#regras-do-item) |

<Warning>
  A régua de validação **não** mora em `rules`. O que reprova e o que é ressalva vive na [régua da organização](/api-reference/kyc/regua-e-metricas). A única exceção é `maxAgeDays`, que vence o prazo da régua para aquele pedido.
</Warning>

## Modelos de termo

Prefixo `/v1/consent-templates`. Criar e editar exige `kycEnabled`; listar e consultar não.

| Método | Caminho | O que faz |
| --- | --- | --- |
| `GET` | `/consent-templates` | Lista os modelos visíveis |
| `POST` | `/consent-templates` | Cria um modelo da organização |
| `GET` | `/consent-templates/{id}` | Consulta |
| `PUT` | `/consent-templates/{id}` | Publica uma versão nova |
| `POST` | `/consent-templates/variables` | Variáveis que o termo pode usar |
| `POST` | `/consent-templates/import` | Importa um contrato em Word e devolve o rascunho |
| `POST` | `/consent-templates/document/presign` | Prepara o envio do PDF do termo |
| `POST` | `/consent-templates/document` | Confirma o PDF enviado e devolve o rascunho |
| `POST` | `/consent-templates/{id}/preview` | Pré-visualiza o termo com dados de exemplo |

### Listar

| Query | Nota |
| --- | --- |
| `scope` | `SYSTEM` (da GYRA+, você vê mas não edita) ou `ORGANIZATION` |
| `entityType` | `COMPANY` ou `PERSON`. Ausente no modelo quer dizer que ele serve os dois |
| `signatureMode` | `INDIVIDUAL` ou `JOINT` |
| `search` | Casa por nome ou pela chave, sem acento e sem caixa |
| `onlyCurrent` | Só a versão vigente de cada linhagem |
| `skip` / `take` | Paginação |

### Criar ou publicar

```json
{
  "key": "CONTRATO_ADESAO",
  "name": "Contrato de adesão",
  "description": "Versão revisada pelo jurídico em setembro.",
  "entityType": "COMPANY",
  "signatureMode": "JOINT",
  "sourceKind": "MARKDOWN",
  "bodyMarkdown": "A empresa <<companyName>>, CNPJ <<cnpj>>, representada por <<username>> (CPF <<cpf>>), declara...\n\nFaturamento informado: <<form.faturamento-medio-mensal>>.\n\nPartes:\n\n<<partes>>\n\nAssinado em <<date>>, IP <<ip>>. Verificação: <<hash>>."
}
```

| Campo | Nota |
| --- | --- |
| `key` | Chave estável do modelo (por exemplo `SCR_PJ`). Acompanha a linhagem entre versões |
| `name` | |
| `description` | |
| `bodyMarkdown` | O texto do termo, com as variáveis |
| `entityType` | `COMPANY`, `PERSON` ou ausente (serve os dois) |
| `signatureMode` | `INDIVIDUAL` ou `JOINT` |
| `sourceKind` | `MARKDOWN` (o texto do editor) ou `PDF` (o arquivo do jurídico) |
| `fileId` / `fileUrl` | O arquivo original, quando veio de upload |
| `fields[]` | Caixas posicionadas sobre o PDF |
| `pageCount` | Páginas do PDF enviado |

### Caixas sobre o PDF

Quando `sourceKind` é `PDF`, `fields[]` posiciona o que será carimbado. Espécies aceitas: `SIGNER_NAME`, `SIGNER_DOCUMENT`, `SIGNER_EMAIL`, `SIGNED_AT`, `ORGANIZATION`, `SUBJECT_NAME`, `SUBJECT_DOCUMENT`, `SIGNATURE`, `CONTENT_HASH`.

### Variáveis

`POST /v1/consent-templates/variables` devolve o vocabulário disponível para aquele contexto: o conjunto fixo, as chaves do formulário da solicitação e os campos extraídos dos documentos do cadastro.

| Forma | Exemplo | De onde vem |
| --- | --- | --- |
| Fixa | `<<username>>`, `<<cnpj>>`, `<<date>>`, `<<ip>>`, `<<hash>>`, `<<partes>>` | Cadastro, destinatário, ato de assinar, via assinada |
| Formulário | `<<form.faturamento-medio-mensal>>` | Resposta do item `FORM` da mesma solicitação |
| Documento | `<<doc.CONTRATO_SOCIAL.companyName>>` | Campo extraído; o caminho pode ser aninhado |

A lista completa está em [Termos e assinatura](/kyc/termos-e-assinatura#variáveis-do-termo).

### Importar de Word

`POST /v1/consent-templates/import` recebe um `.docx` e devolve o rascunho do termo já em Markdown, para o jurídico revisar antes de publicar.

### Pré-visualizar

`POST /v1/consent-templates/{id}/preview` renderiza o termo com dados de exemplo. É como conferir se uma variável ficou sem valor antes de o cliente ver.
