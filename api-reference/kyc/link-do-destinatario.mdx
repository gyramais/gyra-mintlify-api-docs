<Info>
  **Resumo:** estas rotas são a superfície que o cliente final usa. Elas **não usam token de API**: o próprio token do link é a credencial, e ele escopa tudo à pessoa e aos itens dela. Você só precisa desta página se for construir a sua própria interface de coleta em vez de usar a nossa.
</Info>

<Warning>
  Não chame estas rotas do seu backend com o token de outra pessoa. Elas existem para a página que aquela pessoa abriu, e a trilha registra o que acontece nelas como ação **do destinatário**.
</Warning>

## O token

Prefixo `/public/collection/{token}`.

O token tem 43 caracteres (`[A-Za-z0-9_-]`) e identifica **um destinatário** de uma solicitação. Ele é o caminho inteiro do link curto:

```
https://envio.gyramais.com.br/{token}
```

## Limites

| Proteção | Valor |
| --- | --- |
| Requisições por token | 30 por minuto |
| Requisições por IP | 120 por minuto |

Estouro responde `429` com mensagem em português. O token nunca é gravado nem registrado em log: o que se guarda é o hash dele.

## Rotas

| Método | Caminho | O que faz |
| --- | --- | --- |
| `GET` | `/public/collection/{token}` | Estado do link: itens, marca, prazo |
| `POST` | `/public/collection/{token}/new-link` | Pede um novo link a quem solicitou |
| `POST` | `/public/collection/{token}/items/{itemId}/presign` | Prepara o envio de um arquivo |
| `POST` | `/public/collection/{token}/items/{itemId}/confirm` | Confirma o arquivo e dispara a análise |
| `POST` | `/public/collection/{token}/items/{itemId}/form` | Registra as respostas do formulário |
| `POST` | `/public/collection/{token}/items/{itemId}/consent` | Registra o consentimento aceito |
| `POST` | `/public/collection/{token}/items/{itemId}/identity/start` | Abre a sessão de verificação de identidade |
| `POST` | `/public/collection/{token}/items/{itemId}/identity/email/code` | Valida+: envia o código a um e-mail conhecido |
| `POST` | `/public/collection/{token}/items/{itemId}/identity/email/verify` | Valida+: confere o código |
| `POST` | `/public/collection/{token}/items/{itemId}/signatories` | Inclui outra parte no documento conjunto |
| `POST` | `/public/collection/{token}/items/{itemId}/signatories/{signatoryId}/contact` | Informa o contato de uma parte já nomeada |
| `POST` | `/public/collection/{token}/items/{itemId}/signatory-identity/email/code` | Valida+ da parte: envia o código |
| `POST` | `/public/collection/{token}/items/{itemId}/signatory-identity/email/verify` | Valida+ da parte: confere o código |
| `POST` | `/public/collection/{token}/items/{itemId}/signature/code` | Envia o código de confirmação da assinatura |
| `POST` | `/public/collection/{token}/items/{itemId}/signature` | Registra a assinatura eletrônica |

## Estado do link

`GET /public/collection/{token}`

Devolve o que a página precisa desenhar: quem pediu (com logo e cores), o prazo, e a lista de itens daquela pessoa com status, rótulo, instruções, formatos aceitos e o resultado de cada um. Nada de outros destinatários aparece aqui.

Link vencido responde com o estado que permite pedir um novo:

`POST /public/collection/{token}/new-link` registra o pedido. Quem **reemite** é o operador, nunca a página.

## Enviar um arquivo

<Steps>
  <Step title="Presign">
    ```json
    {
      "fileName": "contrato-social.pdf",
      "size": 1843200,
      "mimeType": "application/pdf",
      "fieldKey": "anexo-contrato"
    }
    ```

    `fieldKey` só é usado quando o arquivo responde a uma **pergunta de arquivo** dentro de um formulário. Formatos e tamanho aceitos vêm das regras daquele item.
  </Step>
  <Step title="PUT no armazenamento">
    Suba o arquivo direto na URL assinada, com o mesmo `Content-Type` e o mesmo tamanho declarados.
  </Step>
  <Step title="Confirmar">
    ```json
    { "key": "collection/.../8f2c....pdf", "fileName": "contrato-social.pdf" }
    ```

    Dispara a análise. O item vai para `SUBMITTED` e depois `PROCESSING`.
  </Step>
</Steps>

## Formulário

`POST /public/collection/{token}/items/{itemId}/form`

O corpo traz as respostas por chave (preset ou chave do campo livre). Cada valor é validado contra o tipo declarado no modelo: CPF e CNPJ conferem dígito, `EMAIL_CORPORATE` recusa domínio gratuito, `SELECT` só aceita opção da lista.

Quando a pessoa corrige um valor que a extração tinha sugerido, ou contesta um campo ancorado na fonte oficial, isso entra na trilha e (no segundo caso) manda o item para a revisão do operador.

## Consentimento

`POST /public/collection/{token}/items/{itemId}/consent`

```json
{ "accepted": true, "termVersion": "3" }
```

| Campo | Nota |
| --- | --- |
| `accepted` | O aceite precisa ser explícito |
| `termVersion` | A versão do termo **que foi exibida na página**. Versão diferente da vigente é recusada, para ninguém aceitar um texto que já mudou |

Com `rules.requireIdentity` no item, o aceite só é registrado depois da identidade confirmada.

## Verificação de identidade

`POST /public/collection/{token}/items/{itemId}/identity/start` abre a sessão e devolve a URL que a pessoa abre no celular. O caminho (com documento, sem documento) vem do item.

### Valida+

`POST .../identity/email/code`

```json
{ "candidateId": "c1" }
```

Os candidatos vêm no estado do link, **mascarados** (até 5). O endereço não é escolhido por ninguém: é o que o bureau associa àquele CPF/CNPJ.

`POST .../identity/email/verify`

```json
{ "code": "483920" }
```

| Limite | Valor |
| --- | --- |
| Validade do código | 10 minutos |
| Tentativas por código | 5 |
| Espera entre reenvios | 60 segundos |
| Desafios por dia, por destinatário | 5 |

As mesmas duas rotas existem em `signatory-identity/...` para resolver a identidade de uma **parte** de um documento conjunto.

Falhar aqui não fecha porta: o face match continua disponível, e a troca de método fica na trilha.

## Assinatura

`POST /public/collection/{token}/items/{itemId}/signature/code` envia por e-mail o código de confirmação.

`POST /public/collection/{token}/items/{itemId}/signature`

```json
{
  "accepted": true,
  "name": "Ana Souza",
  "document": "52998224725",
  "code": "483920"
}
```

Num item `JOINT`, a assinatura registra **aquela parte**. O item só fecha (e a via em PDF só nasce) quando todas as partes obrigatórias assinarem. Com `signaturePackage: SIGNATURE_AND_IDENTITY`, a parte fica em `AWAITING_IDENTITY` até a verificação voltar aprovada.

## Convidar outra parte

`POST /public/collection/{token}/items/{itemId}/signatories` (responde `201`)

```json
{
  "name": "Bruno Lima",
  "document": "52998224725",
  "email": "bruno@exemplo.com.br",
  "role": "Sócio administrador"
}
```

E-mail **ou** telefone é obrigatório: sem contato não há para onde mandar o link.

Para uma parte que o próprio documento já nomeou mas de quem ninguém tem o contato, use `POST .../signatories/{signatoryId}/contact` com o e-mail ou o telefone.

## Tempo real

A página escuta um canal em tempo real e atualiza sozinha quando um item muda de estado. O nome do canal é derivado do token por HMAC, então quem tiver só o hash guardado não consegue escutar o canal de ninguém.
