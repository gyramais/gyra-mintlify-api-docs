<Info>
  **Resumo:** as mensagens desta página foram extraídas do código dos serviços e, quando marcadas como verificadas, de chamadas reais à API. Elas vêm em **português** e são o texto exato que chega no campo `message`.
</Info>

## Formato

```json
{
  "code": 400,
  "message": "URL de webhook inválida."
}
```

| Campo | Tipo | Descrição |
|---|---|---|
| `code` | number | Código HTTP. |
| `message` | string | Mensagem em português. Em erros de validação de payload, traz **todas** as falhas concatenadas por vírgula. |

<Warning>
  **Não faça match exato de string** para tratar erro. As mensagens mudam sem aviso e algumas concatenam várias falhas numa só. Use o `code` para a lógica e a `message` para log e exibição.
</Warning>

## Autenticação

| Código | Mensagem | Causa |
|---|---|---|
| `400` | `"ClientId inválido."` | O `gyra-client-id` não corresponde a nenhum usuário. |
| `401` | `"ClientSecret inválido."` | O `gyra-client-secret` está errado para esse client id. |
| `401` | `"Token de acesso inválido."` | JWT ausente, malformado ou expirado. Reautentique. |
| `400` | `"Erro ao fazer login. Email e/ou senha incorreto(s)."` | Login por e-mail e senha com credencial errada. |
| `401` | `"Erro ao fazer login. Este email está vinculado à uma conta do Google."` | A organização exige SSO para esse usuário. |

<Note>
  Repare na assimetria: client id errado dá **400**, secret errado dá **401**. Se você trata só 401 como "credencial inválida", o caso do id errado escapa.
</Note>

## Permissão

| Código | Mensagem | Causa |
|---|---|---|
| `403` | `"Você não tem permissão para acessar este recurso."` | O papel do usuário não cobre o endpoint. |
| `403` | `"Você não tem permissão para usar esta funcionalidade."` | Funcionalidade não liberada para a organização. |
| `403` | `"Você não possui plano de assinatura."` | Organização sem plano ativo. |
| `401` | `"Você não tem permissão para reanalisar esse relatório."` | **Verificado.** Credencial de integração não reanalisa; exige usuário com alçada de revisão. |
| `401` | `"Não autorizado."` | Acesso negado sem detalhamento. |

## Relatório

| Código | Mensagem | Causa |
|---|---|---|
| `404` | `"Relatório não encontrado"` | ID inexistente **ou de outra organização**. O 404 é proposital, para não revelar a existência de relatórios de terceiros. |
| `404` | `"Seção não encontrada"` | A seção não existe nesse relatório. |
| `404` | `"Tipo de seção não encontrado"` | O `sectionType` informado não é um tipo válido. |
| `400` | `"Sessão ainda não finalizada. Aguarde finalizar..."` | O relatório ainda está processando. |

### Exportação

| Código | Mensagem | Causa |
|---|---|---|
| `400` | `"type must be one of the following values: REPORT, REPORT_MINIFIED,type should not be empty"` | **Verificado.** O parâmetro `type` é obrigatório. Use `type=REPORT`. |

<Note>
  As rotas de exportação respondem **`202 Accepted`**, não `200`. Ver [Exportar Relatório](/api-reference/report/get-reportexport).
</Note>

## Política de crédito

| Código | Mensagem | Causa |
|---|---|---|
| `400` | `"Política não está habilitada para ser utilizada"` | A política existe mas está inativa. |
| `400` | `"Não existe política de crédito associada"` | O relatório foi criado sem política. |
| `400` | `"A política encontrou um erro ao ser processada."` | Falha na avaliação das regras. |
| `404` | `"Política não encontrada."` | `policyId` inexistente ou removido. |

## Comitê de Crédito IA

| Código | Mensagem | Causa | Repetir |
|---|---|---|---|
| `400` | `"Os pareceres por seção ainda não finalizaram. Aguarde a conclusão para convocar o comitê."` | O relatório ainda gera pareceres. | **Sim**, com backoff |
| `400` | `"A política de crédito ainda não concluiu. Aguarde o resultado da política para convocar o comitê."` | Resultado da política não chegou. | **Sim**, com backoff |
| `400` | `"O comitê de crédito não está habilitado para a política deste relatório."` | Política sem pipeline de parecer. | Não |
| `400` | `"Nenhum parecer por seção disponível para deliberação do comitê."` | Nenhuma seção produziu parecer. | Não |
| `409` | `"O comitê já está em deliberação para este relatório."` | Deliberação em andamento. | Não, aguarde o webhook |

Detalhes do padrão de retry em [Convocar Comitê](/api-reference/report/post-reportcommittee).

## Webhook

| Código | Mensagem | Causa |
|---|---|---|
| `400` | `"URL de webhook inválida."` | **Verificado.** A GYRA+ faz um `POST` de teste na sua URL antes de salvar. Se ela não responder `2xx`, o cadastro é recusado. Ver [Criar Webhook](/api-reference/webhook/post-webhook). |
| `400` | `"type must be one of the following values: REPORT, OPTIN, CREDIT_POLICY, REPORT_STATUS, REPORT_FINISHED, REPORT_EXPORTED, COMMITTEE_FINISHED, OPERATION..."` | Tipo de webhook inválido ou ausente. |

## Autorização de SCR (opt-in)

| Código | Mensagem | Causa |
|---|---|---|
| `400` | `"Documento não possui autorização de consulta do SCR."` | Falta o opt-in do titular. |
| `400` | `"Documento não assinou a autorização de consulta do SCR."` | Solicitação enviada e não assinada. |
| `400` | `"A autorização de consulta SCR foi revogada."` | Titular revogou. |
| `400` | `"A solicitação está expirada. Solicite o reenvio"` | Prazo vencido. |
| `400` | `"A solicitação está pendente. Aguarde ou reenvie."` | Ainda não respondida. |
| `400` | `"Documento já cadastrado para outra solicitação nesta organização"` | Já existe solicitação para esse documento. |
| `400` | `"Documento inválido"` | CPF ou CNPJ com dígito verificador inválido. |

## Erros de servidor

| Código | Quando |
|---|---|
| `500` | Erro inesperado. Se persistir, acione `atendimento@gyramais.com` com o `reportId` e o horário. |
| `502` / `504` | Falha ou timeout numa fonte externa durante a análise. O relatório pode concluir com a seção em erro, em vez de falhar inteiro: confira `errors` na seção. |

## Boas práticas

<AccordionGroup>
  <Accordion title="Trate pelo código, não pela mensagem">
    As mensagens são texto de UI e mudam. Erros de validação concatenam várias falhas numa string só, então match exato quebra fácil.
  </Accordion>
  <Accordion title="Separe transitório de definitivo">
    `400` de "ainda não finalizou" pede retry com backoff; `400` de "não habilitado" não muda com o tempo. A tabela do comitê marca isso na coluna **Repetir**.
  </Accordion>
  <Accordion title="404 nem sempre é 'não existe'">
    Relatório de outra organização também devolve `404`, de propósito, para não vazar a existência de dados de terceiros. Se você tem certeza de que o ID existe, confira o token usado.
  </Accordion>
  <Accordion title="Erro de seção não derruba o relatório">
    Uma fonte que falha registra o problema em `errors` daquela seção e o relatório segue. Verifique esse campo antes de assumir que o dado simplesmente não existe.
  </Accordion>
</AccordionGroup>
