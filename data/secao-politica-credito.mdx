<Info>
  **Resumo:** a seção `CREDIT_POLICY` traz o resultado da avaliação da política: status, score, faixa de risco e o detalhamento por grupo de regras.
</Info>

<Warning>
  **Não há exemplo completo desta seção nesta página, de propósito.** O payload real é grande demais: chega em 13 fragmentos de `sectionDetails` e o detalhamento por grupo de regras é extenso. Um dump inteiro seria ilegível e envelheceria rápido.

  O que está abaixo é um **trecho real**, anonimizado, para você reconhecer o formato. Para o payload completo do seu caso, chame [`GET /report/{id}/section/{sectionType}`](/api-reference/report/get-report-section) com o seu relatório. Para a leitura já interpretada, sem lidar com o bruto, use [`GET /report/{id}/insights`](/api-reference/report/get-reportinsights).
</Warning>

### Trecho real

```json
{
  "id": "6612a7f340388f1300000000",
  "policyId": "6612a7f3625ea4ab00000000",
  "policyVersion": 1.11,

  "document": "43591367000130",
  "yearMonth": 20260731
}
```

## Campos reais

| Campo | Tipo | Descrição |
|---|---|---|
| `id` | string | ID do resultado da política. |
| `policyId` | string | Política aplicada. |
| `policyVersion` | number | Versão da política no momento da análise. |
| `version` | number | Versão do registro de resultado. |
| `status` | string | Resultado da política: `APPROVED`, `DENIED`, `ALERT`. |
| `score` | number | Score final calculado (1 a 1000). |
| `scoreStatus` | string | Status derivado da faixa de score. |
| `risk` | object | Faixa de risco em que o score caiu. |
| `policyRuleGroupResults` | object[] | Resultado por grupo de regras. É onde está o detalhe do que passou e do que barrou. |
| `missingOptins` | array | Opt-ins que faltaram para avaliar alguma regra. |
| `document` | string | Documento analisado. |
| `yearMonth` | number | Data de referência no formato `AAAAMMDD`. |
| `organizationId` | string | Organização. |
| `references` | object[] | Ponteiros para o registro de origem: `{ id, collectionName, microServiceName }`. |
| `createdAt` / `updatedAt` | datetime | Datas do registro. |

<Note>
  Assim como o Resumo, esta seção chega **fragmentada** em `sectionDetails` (13 fragmentos no relatório verificado). Junte as chaves de todos os itens antes de ler.
</Note>
