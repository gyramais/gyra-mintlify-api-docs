<Info>
  **Resumo:** a seção `SUMMARY` é a única que **não tem um formato fixo**. Ela é montada por fragmentos: cada fonte que respondeu adiciona o seu próprio bloco ao array `sectionDetails`. No relatório que usamos para verificar, eram **16 fragmentos**.
</Info>

<Warning>
  **Não há exemplo completo desta seção nesta página, de propósito.** O payload real é grande demais: chega em 16 fragmentos de `sectionDetails` e cada fonte adiciona o seu bloco. Um dump inteiro seria ilegível e envelheceria rápido.

  O que está abaixo é um **trecho real**, anonimizado, para você reconhecer o formato. Para o payload completo do seu caso, chame [`GET /report/{id}/section/{sectionType}`](/api-reference/report/get-report-section) com o seu relatório. Para a leitura já interpretada, sem lidar com o bruto, use [`GET /report/{id}/insights`](/api-reference/report/get-reportinsights).
</Warning>


## Como ela é montada

Diferente das outras seções, aqui `sectionDetails` não é um item só. Cada entrada traz o resumo de uma fonte, e você precisa **percorrer o array e juntar as chaves**:

```javascript
const resumo = {};
for (const detail of secaoSummary.sectionDetails ?? []) {
  Object.assign(resumo, detail.values ?? {});
}
```

## Blocos de resumo (`*Summary`)

Os cartões do topo do relatório seguem um padrão comum, com `order`, `title`, `tooltip`, `icon`, `value`, `subValue` e `dateText`:

| Bloco | Conteúdo |
|---|---|
| `certificatesSummary` | Certidões emitidas, com `totalCertificates`. |
| `changesSummary` | Alterações cadastrais. |
| `pepSummary` | Exposição política. |
| `lawsuitsSummary` | Processos judiciais. |
| `pefinsSummary` / `refinsSummary` | Restritivos. |
| `checksSummary` | Cheques sem fundo. |
| `serasaScoreSummary` | Score do bureau. |
| `estimatedBillingSummary` / `presumedBillingBaseSummary` | Faturamento estimado e a base usada. |
| `limitGyraSummary` | Limite GYRA+. |
| `creditLimitRecommendationSummary` | Limite recomendado. |
| `nucleaHistoricalReceivingSummary` / `nucleaHistoricalPayingSummary` | Fluxo transacionado (Núclea). |

## Outros campos observados

Certidões individuais (`pgfnCertificate`, `debtAbsenceStateCertificate`, `debtLaborAbsenceCertificate`, `boardCertificate`), cada uma com `valid` e `error`. Dados de PEP (`ownersPep`, `companyPep`), processos (`companyLawsuits`), mudanças (`addressesChanges`, `basicDataChanges`, `economicGroupChanges`) e identificação (`name`, `document`, `formattedDocument`, `situation`, `provider`, `source`, `emissionDate`, `validityDate`, `url`).

<Warning>
  A lista acima é **o que apareceu num relatório COMPLETO+ real**, não um contrato. Quais blocos existem depende das fontes ativadas na política. Sempre verifique a presença da chave antes de usar.
</Warning>
