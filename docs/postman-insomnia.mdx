## Como importar no Postman

<Steps>
  <Step title="Baixe o arquivo">
    Clique no cartão acima para baixar `gyra-postman-collection.json`.
  </Step>
  <Step title="Importe">
    No Postman, **Import** e arraste o arquivo.
  </Step>
  <Step title="Preencha as credenciais">
    Abra a coleção **GYRA+ API**, aba **Variables**, e preencha:

    | Variável | O que colocar |
    | --- | --- |
    | `clientId` | O Client ID gerado em *Configurações, API & MCP* |
    | `clientSecret` | O Client Secret do mesmo par |

    `baseUrl` já vem preenchido e `accessToken` fica vazio de propósito.
  </Step>
  <Step title="Autentique">
    Rode **Autenticacao, Gerar token de acesso JWT**. Um script salva o `accessToken` na variável da coleção, e todas as outras requisições passam a usar esse token.

    O token vale 24 horas. Depois disso, rode a autenticação de novo.
  </Step>
</Steps>

## Como importar no Insomnia

<Steps>
  <Step title="Baixe o arquivo">
    Clique no cartão acima para baixar `gyra-insomnia-collection.json`.
  </Step>
  <Step title="Importe">
    No Insomnia, **Application**, **Import**, e selecione o arquivo.
  </Step>
  <Step title="Preencha o ambiente">
    O ambiente **Base** já vem criado. Preencha `clientId` e `clientSecret`.
  </Step>
  <Step title="Autentique">
    Rode **Autenticacao, Gerar token de acesso JWT** e copie o `accessToken` da resposta para a variável de ambiente de mesmo nome.
  </Step>
</Steps>

<Note>
  No Postman o token é salvo sozinho por um script; no Insomnia você copia uma vez. É a única diferença entre as duas.
</Note>

## Variáveis

| Variável | Valor padrão | Para quê |
| --- | --- | --- |
| `baseUrl` | `https://gyra-core.gyramais.com.br` | Endereço da API |
| `clientId` | vazio | Sua credencial |
| `clientSecret` | vazio | Sua credencial |
| `accessToken` | vazio | Preenchido pela autenticação |

Os corpos de exemplo trazem CNPJ e CPF fictícios, com dígito verificador válido. Troque pelos seus antes de rodar contra a sua organização.

## Um caminho para começar

```
1. POST /auth/authenticate                    token
2. GET  /credit-policy/policy                 escolha uma política ativa
3. POST /v2/report                            crie um relatório
4. GET  /v2/report/{id}                       acompanhe até concluir
5. POST /v1/registry/validate-document        mande um documento e leia o parecer
6. GET  /v1/collection-templates              veja os modelos de coleta
7. POST /v1/webhook/endpoints                 assine os eventos e pare o polling
```

<Tip>
  Precisa de credenciais? Gere você mesmo no toolbox, em **Configurações, API & MCP**. Ver [Chaves de API](/api-reference/api-keys).
</Tip>
